# review-budget

Лёгкий skill для Claude Code, Codex и Opencode: помогает вести разработку
через агентов LLM быстро и без лишних затрат. Он задаёт, сколько ревью,
раундов исправлений и прогонов тестов получает работа и на каких моделях.

[English version](README.md)

## Зачем

Когда ассистент выполняет план через агентов, бо́льшая часть времени уходит на
ожидание. Задача проходит ревью, исправление, повторное ревью исправления и
ещё одно исправление. Весь набор тестов запускается после каждого шага, сборка
релиза — после каждой задачи. Повторное ревью редко находит то, что пропустило
первое. Skill появился на реальном проекте, где такие циклы замедляли работу
сильнее, чем улучшали код.

## Что решает

- одно ревью на задачу вместо цикла повторных
- весь набор тестов — один раз на задачу, а не после каждого шага
- долгая сборка релиза — один раз, в конце
- независимые задачи идут параллельно
- модель и уровень effort для ревьюеров, исполнителей и чтения логов тестов
  выбирает пользователь: никто не платит за самую сильную модель или самый
  высокий effort, не решив этого сам

Skill самостоятельный: другие skills и плагины ему не нужны.

## Алгоритм

Координатор — сессия ассистента, которая раздаёт задачи агентам.

1. **До первого поручения:**
   - один раз спросить, на какой модели и с каким effort работают ревьюеры,
     исполнители и агент, читающий логи тестов; если в плане есть миграция,
     работа над производительностью или крупный рефакторинг, для такой задачи
     предложить самую сильную модель; не спрашивать, если всё это уже
     названо в инструкциях пользователя;
   - составить таблицу зависимостей: какие файлы и интерфейсы у каждой задачи;
   - поднять «тёплую» среду для тестов, если проект это позволяет.
2. **Каждая задача:**
   - исполнитель пишет код и запускает только тесты по своей правке;
     команды, которые остановятся на запрос разрешения, в поручении
     запрещены — ни один агент не ждёт ответа человека;
   - координатор один раз запускает весь набор тестов; длинный лог читает
     агент на дешёвой модели и возвращает только упавшие тесты;
   - одно ревью на модели ревьюера; ревьюер читает этот вывод тестов;
   - один раунд исправлений со всеми находками.
3. **Исправление повторно не ревьюится**, если оно не меняет интерфейс,
   которым пользуется другой код, и не трогает файл, которого нет в находках.
4. **Задачи без общих файлов и интерфейсов** идут одновременно, каждая в своём
   worktree.
5. **В конце:** одно ревью всей ветки, один раунд исправлений, весь набор
   тестов, затем один раз сборка релиза.
6. **Документацию, комментарии, номер версии и исправления в одну строку**
   координатор делает сам.
7. **Небольшую правку после окончания работы** координатор делает сам: одно
   ревью и одна сборка, без нового плана.

## Установка

```bash
git clone https://github.com/vadbosh/review-budget
cd review-budget
./install.sh            # во все ассистенты, найденные в ~/.claude, ~/.codex, ~/.config/opencode
./install.sh --dry-run  # показать, что будет записано
./install.sh --no-rule  # только skill, без правила-триггера
```

Установщик добавляет и правило-триггер `rules/review-budget-trigger.md`. По
нему ассистент загружает skill всякий раз, когда работа идёт через агентов, —
даже если первым загрузился другой skill процесса. Без правила наберите
`/review-budget` (`$review-budget` в Codex) перед работой.

## Модели в разных ассистентах

| Ассистент | Вопрос | Модель и effort агента |
|---|---|---|
| Claude Code | `AskUserQuestion` | `model` и `effort` в каждом вызове `Agent` |
| Codex | `request_user_input` | `model` и `reasoning_effort` в каждом вызове `spawn_agent` |
| Opencode | `question` | `model` в каждом вызове `subagent` в виде `providerID/modelID#variant`; вариант берётся из инструмента моделей (Opencode 2.x) |
